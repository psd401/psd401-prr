# PSD401 Public Records Request System

Custom-built Public Records Act request management for Peninsula School District
No. 401 (WA). Governing law: **RCW 42.56** and **FERPA**. Compliance is the product:
deadline math, exemption handling, and the audit trail are legal artifacts, enforced
at the database level and by focused tests.

## Overview

The application is a Django 6 and DRF backend (`apps/`, `config/`) with a React and
TypeScript staff workspace (`frontend/`) and two MCP transports (`integrations/mcp/`).
Postgres 16 is the runtime database, and tests run on SQLite. Celery with Redis runs
deadlines, watchdogs, Gmail transport, and Vault work. Production is `prr.psd401.net`,
deployed by one CDK command ([aws-deployment.md](operations/aws-deployment.md)).

Compliance rules are enforced in code, not in policy text. The statutory state machine
goes through `services.transition()`, and every redaction cites an exemption. The
audit log and status history are append-only. Footage is auto-held and never
auto-denied. A case's matter kind decides which law it answers to.

## Current status

[`docs/project-status.md`](../docs/project-status.md) is a dated ledger (review of 2026-08-02) that its own header says is not a current status page. For the current gate, use `bash scripts/verify-fast.sh --full` ([testing and quality gates](operations/testing.md)). Phase 2 is implemented in the repository,
including Vault ingest, review and redaction, exemption logs, release, fees, JLARC
reporting, and advisory AI. What remains is operational: district credentials,
approvals, rehearsals, and cutover, tracked in the Phase 2 production handoff document
(an operational document outside this wiki).

## Quick start

```bash
docker compose up -d db redis minio clamav    # backing services; clamav scans intake attachments
uv sync --locked && source .venv/bin/activate  # Python 3.12 deps from uv.lock
PYTHON_DOTENV_DISABLED=1 python manage.py test apps --settings=config.test_settings
python manage.py runserver                     # host-run Django
```

Local development uses Django sessions and never needs Google or AWS access. Production
deploys only with `cd infra/cdk && bunx cdk deploy psd401-prr-prod --require-approval never --profile psd401-prr-prod`.

## Open verification items

- **FERPA disclosure gate.** ADR 0004 and AGENTS.md rule 13 say nothing is disclosed on a
  `ferpa_parent` matter until a named officer records identity verification. Recording
  is implemented (`apps/records/services.py`, `record_ferpa_identity_verification`), but
  no release, installment, or production check consumes the verification row that the
  source inspection found, and no test asserts that refusal. The installment packaging,
  release, and requester download code has no such reference
  ([installments and release](domain/installments-and-release.md#invariants)). Treat it as
  unverified. See [matter kinds](domain/matter-kinds.md#enforcement-status).
- **Meaning of the Gmail activation overlay.** `infra/aws/prr-compose.sh` and the CDK alarm text
  treat the overlay file on the host as the enabled state for inbound polling. `docs/aws-deploy.md`
  says the application setting decides, and the overlay is kept only for a one-time import. The
  source does not settle which applies to a given release. See
  [deployment](operations/deployment.md#host-compose-wrapper) before changing either.
- **Restore-drill release gate.** `docs/backups.md` says the recurring deploy rejects pending
  migrations unless the reviewer pins a completed drill's evidence. The current release script
  in `infra/cdk/lib/prr-hosting-stack.ts` takes an application backup and then runs `migrate`,
  and no drill or migration-digest check was found in `infra/`. The restore verifier
  (`infra/aws/verify-app-backup-restore.sh`) is installed on the host as a command, but nothing in
  `infra/` invokes it during a release. `docs/project-status.md` says
  the release-gate machinery was retired. Treat the drill as a manual procedure until the
  owner confirms. See [backups](operations/backups.md#restore-verifier-and-the-release-ordering).
